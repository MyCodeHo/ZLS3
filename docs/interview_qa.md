# MiniS3 面试准备问答

以下问题围绕该项目的设计、实现与运行，包含建议回答要点。可根据你的实际贡献进行个性化调整。

## 1. 项目整体
**Q1：这个项目解决什么问题？**  
A：实现一个轻量级对象存储服务，支持 bucket 管理、对象上传/下载/删除、分段上传、预签名 URL，具备可观测性与基本性能优化能力，适合作为 S3-like 系统的原型。

**Q2：系统整体架构如何划分？**  
A：分为网络/协议层、API 层、服务/存储层、监控运维层。网络层基于 epoll；API 层由路由与 handler 实现业务；存储层由 MetaStore(MySQL) 和 DataStore(CAS) 组成，GC 清理无引用数据；监控层提供 Prometheus 指标与日志。

## 2. 网络与协议
**Q3：为什么使用 epoll？**  
A：epoll 适合高并发连接场景，支持事件驱动与非阻塞 I/O，减少线程阻塞开销。

**Q4：HttpConnection 如何处理大对象上传？**  
A：采用流式读取 body，边读边写入 DataStore，避免一次性加载到内存；解析器跟踪剩余内容长度，读取完成后触发业务处理。

**Q5：如何处理发送大对象下载？**  
A：使用 sendfile 将文件直接从磁盘发送到 socket，减少用户态拷贝，提高吞吐。

## 3. 数据与一致性
**Q6：为什么使用 CAS 存储？**  
A：CAS 以内容哈希作为 key，天然支持去重与引用计数，结合 GC 能有效管理存储空间。

**Q7：如何保证元数据与数据一致性？**  
A：元数据写入在 MySQL 事务中进行，CAS 引用计数更新与对象/分片记录写入在一个事务里。GC 仅删除 ref_count=0 的 blob。

**Q8：Multipart 如何保证正确性？**  
A：服务端保存每个分片的 etag 和 hash；完成时按 part_number 排序比对客户端提交的 etag，确保一致性后合并 CAS 文件。

## 4. API 设计
**Q9：Bucket/对象 API 的风格是什么？**  
A：REST 风格，使用清晰的资源路径，例如 /buckets/{bucket}/objects/{object}。

**Q10：ETag 在 JSON 和 Header 中的格式如何处理？**  
A：Header 保持带引号（兼容 HTTP 语义），JSON 返回去引号的纯值，避免解析混淆。

## 5. 性能与优化
**Q11：你做过哪些性能优化？**  
A：流式上传、sendfile、合理的 socket 缓冲区配置、连接池参数优化、IO 线程分离，降低拷贝与阻塞。

**Q12：测试性能的方法是什么？**  
A：使用脚本进行并发上传/下载基准，记录吞吐与延迟，并结合 Prometheus 指标观察系统瓶颈。

**Q13：为什么本地测试 GET 吞吐量很高？**  
A：因为回环网络与文件缓存导致 IO 延迟极低，不代表真实网络/磁盘环境。

## 6. 稳定性与运维
**Q14：如何处理连接泄漏或空闲连接？**  
A：HttpConnection 设置空闲超时，超时后强制关闭连接。

**Q15：如何进行故障排查？**  
A：看访问日志、错误日志、Prometheus 指标；定位瓶颈是网络、磁盘还是数据库。

## 7. 数据库与事务
**Q16：为什么使用 MySQL，而不是 KV？**  
A：MySQL 便于事务与复杂查询，并且已有成熟运维体系，适合元数据管理。

**Q17：连接池如何配置？**  
A：基于并发程度设置 pool_size，避免频繁建连与上下文切换。

## 8. 安全与认证
**Q18：鉴权怎么做？**  
A：使用静态 token 的 Bearer 认证，适合开发环境；生产可扩展为更复杂的鉴权机制。

## 9. 代码与工程
**Q19：如何组织项目结构？**  
A：网络层、API 层、存储层、工具层分离，模块边界清晰，便于扩展和测试。

**Q20：测试覆盖范围有哪些？**  
A：单元测试覆盖核心工具与解析逻辑，集成测试覆盖存储与 API 行为，脚本覆盖端到端验证。

## 10. 可扩展方向
**Q21：如果要加入版本控制/多副本，你会怎么做？**  
A：扩展对象元数据为多版本记录，存储层增加副本策略；读写路径需要感知版本与副本一致性。

**Q22：如何支持分布式？**  
A：引入元数据服务与一致性哈希路由，数据节点使用副本/纠删码，客户端或网关负责路由。

## 11. 行为与贡献
**Q23：你在项目里具体做了哪些工作？**  
A：可按实际工作描述，例如完善 MetaStore 事务、实现流式上传、修复 ETag 兼容、完善测试脚本与性能评估等。

**Q24：遇到的难点是什么？**  
A：大对象流式处理与元数据一致性，解决方式是引入 body 流式消费和 ref_count 事务。

## 12. 快速复述模板
**Q25：请 1 分钟介绍项目。**  
A：MiniS3 是一个轻量级对象存储服务，核心是 epoll 驱动的 HTTP 服务 + MySQL 元数据 + CAS 文件存储。支持 bucket 和对象 CRUD、分段上传、预签名 URL，并提供 Prometheus 指标与日志。重点优化了大对象流式上传和 sendfile 下载，保证性能与稳定性。
